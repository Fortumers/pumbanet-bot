# PumbaNET Bot

Статус: начальный проверяемый модуль правил, НЕ готовый Telegram-бот.
Нельзя запускать продажи или считать проект выполнением полного ТЗ.

## Реализовано

- Неизменяемый снимок тарифа.
- Проверка соответствия платежа заказу, пользователю, сумме и валюте.
- Повтор одного платежа не меняет заказ; другой платёж отклоняется.
- Планирование абсолютной даты продления и повторное использование цели.
- Подтверждение результата по наблюдаемой дате панели.
- Проверка ASCII-чисел и HTML-экранирование без удаления символов.
- Автоматические unit-тесты без внешних зависимостей.

## Проверка

Python 3.11 или новее:

```sh
python -m unittest discover -s tests -v
```

## Границы гарантий

Модуль не аутентифицирует события оплаты и не вызывает Remnawave.
Объект Payment должен создаваться только доверенным адаптером после проверки
серверного события, а не из пользовательского сообщения или callback.
В памяти обеспечены правила одного заказа, а НЕ распределённая идемпотентность.
База и транзакции пока не реализованы. До выдачи в production нужны:

- уникальный (provider, charge_id) глобально по всем заказам;
- блокировка заказов и сериализация выдачи на одного VPN-пользователя;
- атомарная запись платежа, статуса и outbox-задачи;
- фиксация target_expiry до HTTP-запроса;
- сверка с панелью после неоднозначного таймаута;
- проверка реального аккаунта, групп, лимитов и subscription URL;
- шифрованное хранение чувствительных ссылок и доставка через outbox.

finish_provisioning проверяет только дату. Это НЕ достаточная проверка
полноценного доступа, поэтому пользовательские сообщения об успехе отсутствуют.

## Не реализовано

Aiogram-интерфейс, PostgreSQL, Alembic, Redis, очередь, Remnawave-адаптер,
Stars-адаптер, HTTP-сервис, тарифная админка, RBAC, тикеты, переносы,
промокоды, рефералы, устройства, пробный доступ, подарки, рассылки,
напоминания, резервное копирование, Docker и установка на сервер.
Все эти функции недоступны; кнопок-заглушек нет.

## Интеграции

Нужны версия и очищенная OpenAPI-схема установленной Remnawave.
Не добавляйте реальные токены или ссылки клиентов в репозиторий.
Для цифровых услуг внутри Telegram проектировать оплату в Stars (XTR):
https://core.telegram.org/bots/payments-stars
Доступ выдается только после successful_payment, не pre_checkout_query.
Необходимы /terms, /support, /paysupport и обработка возвратов.

Следующая стадия: PostgreSQL-модели, миграции и transactional outbox с
интеграционными тестами параллельных платежей и восстановления после сбоя.
